# Agent Runtime Operator Control Plane — ADR

Status: **partial internal control bridge implemented and tested; not deployment-ready**  
Scope: isolated Agent Runtime Preview only. This ADR does not authorize a Durable Object namespace, binding, secret injection, deployment, task execution, or Production change.

## Current implementation (2026-11-23)

The current branch contains the following Worker-to-State-Store routes:

- `GET /internal/control`
- `POST /internal/control/pause`
- `POST /internal/control/resume`
- `GET /internal/usage`
- `GET /internal/task?id=...`
- `POST /internal/recover` (only when both outer runtime gates are explicitly open)

The control mutation bridge requires the external `AGENT_OPERATOR_TOKEN`, a configured `AGENT_OPERATOR_ID`, and a separate `AGENT_STATE_STORE_TOKEN` for the internal Durable Object call. The Worker creates the actor and request ID; callers cannot supply an actor. The State Store persists pause state, control audit events, and a per-actor rate limit (10 mutations per 60-second window). The Durable Object is declared only in the separate `wrangler.preview.jsonc` config; the default `wrangler.jsonc` validation shell remains unbound. A dedicated Worker named `ai-thuc-chien-agent-runtime-preview` was previously verified in Cloudflare Preview with four SQLite Durable Object namespaces (`AgentStateStore`, `AgentReviewerAuthStore`, `AgentDraftStore`, and `AgentAIBankCandidateStore`) plus an `AGENT_STATE_STORE_TOKEN` binding. Its deployed source was the older commit `8a470ad5dd1f59e96aff9ec37bf85697e79e1dcb`, not the current PR #327/#368 reviewed head. This does not prove exact-head deployment or Runtime E2E readiness.

Control mutation request bodies are bounded before JSON parsing: 1 KiB at Worker ingress and 16 KiB independently at the State Store. Declared lengths and streamed bytes are checked; oversized bodies return 413 and malformed JSON returns 400. The control JSON parser accepts only the string fields `reason`, `actor`, and `requestId`, rejects unknown fields and duplicate keys, and preserves the Worker/State Store distinction: the external Worker accepts only `reason`, while the internal State Store accepts the actor and request ID generated by the Worker. The isolated Agent Runtime suite previously passed 67/67 tests on code commit `61bbd1d49feaac32933d0217d1418b2eae4ed7cb`; the separate GitHub OIDC verifier added later in this PR has its own targeted tests and is not yet counted in that result.

The current operator identity is a static deployment-configured label, **not proof of an authenticated human identity**. The shared bearer token does not provide named-user attribution, MFA, session expiry, revocation per person, or role-based permissions. Do not describe this bridge as a browser-safe operator console or as a verified human identity system.

The operator-auth unit tests also verify that replacing the configured operator secret invalidates the previous bearer and that the operator and Worker-to-State-Store credentials cannot authenticate across trust boundaries. This proves code-level rotation semantics only; it does not establish an operational secret-rotation runbook or person-level revocation. The State Store and Worker code are covered by isolated tests, but the control routes are not deployment approval. The Runtime remains disabled by default, unbound, and without a task handler or scheduler.

The GitHub Actions OIDC path is now wired in code for one least-privilege operation: `POST /internal/oidc/pause`. It obtains discovery/JWKS only from the fixed GitHub issuer, rejects redirects and untrusted JWKS locations, verifies RS256 plus the exact audience/repository/owner IDs/main ref/workflow ref/actor ID/event/run/time claims, and atomically consumes the `jti` in the State Store before writing the Pause action. The new manual GitHub Actions workflow grants only `contents: read` and `id-token: write`; it exposes no Resume or task-execution operation. The repository Preview config keeps the runtime disabled and paused, reviewer authentication disabled, and OIDC enabled only for the manual main-ref Pause-only workflow with actor ID `342528485`. This is a least-privilege emergency Pause path, not general operator authorization. The deployed Worker is still on the older source SHA above; no exact-head Runtime E2E, independent security review, or Free-tier headroom evidence has been established.

## Trust boundaries and limitations

1. **External caller** — controlled operator tooling only. Do not put the shared bearer token in browser JavaScript, public pages, URLs, logs, or client-side storage.
2. **Worker ingress** — validates the external bearer, validates the fixed route and request fields, creates the configured actor and request ID, and forwards only the dedicated internal credential.
3. **Worker-to-State-Store call** — uses the fixed Durable Object identity and fixed internal paths. Caller cookies, Origin, Authorization, and arbitrary headers are not forwarded.
4. **State Store** — accepts only the separate internal service credential and applies transactional state changes, persistent rate limiting, and audit recording.

Before any broader operator access, replace the shared-token-only ingress with a verified identity/session layer. Prefer a no-cost, already-entitled identity gateway with MFA and a named-operator allowlist. If its free entitlement cannot be verified, keep operator mutation unavailable. Do not invent a home-grown password store or expose a public bearer-token endpoint.

## Implemented permissions and routes

| Route | Current behavior | Limitation |
|---|---|---|
| `GET /internal/control` | Read persisted pause state | Shared bearer only |
| `POST /internal/control/pause` | Persist pause and audit action | Static actor label; no human identity proof |
| `POST /internal/control/resume` | Persist resume and audit action | No second-person approval or independent health gate |
| `GET /internal/usage` | Return allowlisted usage counters | No global read-rate limit |
| `GET /internal/task?id=...` | Return allowlisted task metadata | Shared bearer only |
| `POST /internal/recover` | Recover one expired lease and return minimized task state | Requires both outer runtime gates open; service actor is not human identity |
| `POST /internal/oidc/pause` | Verify GitHub Actions OIDC, consume `jti`, and persist Pause | Manual workflow only; disabled by default; actor ID must be configured; no Resume |

`POST /internal/recover` is now present in Worker source and covered by targeted tests. It requires the operator bearer, both outer runtime gates (`AGENT_ENABLED=true` and `AGENT_PAUSED=false`), a configured static service-actor label, a bounded task ID, and the separate internal State Store credential. The Worker generates the request ID and forwards only the fixed internal request. The State Store enforces its durable per-actor 10-per-60-second rate limit and records actor/request ID in the recovery audit event. It can only requeue/fail a task after its lease has expired; it does not execute a task. This is code-only and undeployed. The static actor label is not human identity; do not expose the shared bearer in browser code.

## Pause and resume semantics

- The persisted control row lives in the same Durable Object as task state so pause checks and task admission/claim transactions share a serialization boundary.
- Deployment flags remain independent outer gates: `AGENT_ENABLED=true` and `AGENT_PAUSED=false` are still required before admission or claims.
- A persisted pause blocks new reservations, new claims, and lease recovery.
- A task already holding a valid lease may heartbeat and complete while paused so it can reach a safe terminal state.
- Pause does **not** forcibly interrupt an already-running external side effect. Future handlers must support cooperative cancellation or document their non-interruptible boundary.
- Resume does not automatically dispatch queued work. No dispatcher or task handler exists.
- Missing or unreadable control state must fail closed.

## Security gaps before deployment or broader exposure

- **GitHub OIDC (manual Pause-only path):** the verifier is wired to `POST /internal/oidc/pause`. It uses the fixed GitHub issuer/JWKS endpoint, rejects redirects and untrusted JWKS locations, verifies RS256 plus the configured audience/repository/owner/ref/workflow/actor/event/run/time claims, and atomically consumes the `jti` in the State Store before Pause. It does not authorize Resume, Recovery, or task execution. The source config enables only the manual main-ref Pause-only workflow; independent third-party review and exact-head E2E remain outstanding. Never treat a valid signature alone as sufficient for Resume.
- **Human identity and revocation:** `AGENT_OPERATOR_ID` is static configuration. A shared bearer holder can perform mutations under that label; the audit trail is not person-level attribution. Replacing the configured `AGENT_OPERATOR_TOKEN` invalidates the previous bearer immediately, but this is whole-token rotation—not per-person revocation, session expiry, or named-user identity. Rotation requires a controlled Preview secret update and must never be performed against Production under this ADR.
- **MFA/session lifecycle:** no MFA, short-lived session, per-user revocation, or role-based authorization is implemented.
- **Browser protections:** no cookie session, CSRF token, or Origin validation is implemented. Keep the bridge off browser-facing surfaces.
- **Request body bounds and strict parsing:** implemented on the current branch. The Worker rejects control mutation bodies above 1 KiB; the State Store independently rejects control mutation bodies above 16 KiB. Both enforce declared `Content-Length` and count streamed bytes before JSON parsing. The parser accepts only the expected string fields, rejects unknown and duplicate keys, and does not relax the Worker’s external request schema. Targeted tests cover oversized declared bodies, oversized chunked bodies, malformed JSON, duplicate external/internal fields, and unchanged control state after rejection. These limits reduce memory/parse exposure but do not replace ingress rate limiting or slow-client protection.
- **Rate limiting:** persistent limit is per configured actor; because the actor is static, it is not a per-human limit. There is no separate global ingress limit, and read routes are not rate-limited.
- **Audit semantics:** the audit table records state-changing pause/resume events. Idempotent no-op requests and rejected attempts are not represented as completed state-change audit rows. Add access-controlled security-event logging if operational attribution requires those events.
- **Resume assurance:** current route checks the bearer and configured actor but does not independently verify account plan, resource health, or an approval confirmation.
- **Deployment:** a dedicated Runtime Preview Worker and four Durable Object namespaces exist, with a State Store token binding. The deployed source is the older SHA `8a470ad5dd1f59e96aff9ec37bf85697e79e1dcb`, not the current PR #327/#368 head. Exact-head deployment/E2E remains blocked; no Production resources have been changed.

## Required acceptance gates

1. Verify a no-cost identity/session option and actual account entitlement; no paid upgrade, billing activation, or payment setup.
2. Threat-model operator compromise, replay, token theft, session theft, rate-limit bypass, and internal-token exfiltration. For any OIDC integration, require fixed-issuer JWKS retrieval, safe key rotation, exact workflow/actor claims, and atomic durable `jti` consumption.
3. Preserve the implemented 1 KiB Worker and 16 KiB State Store control-body caps; keep regression coverage for declared-length, streamed, and malformed-body rejection.
4. Implement named human identity, MFA, short sessions, revocation, least-privilege roles, and appropriate browser CSRF/Origin protections before any browser-based administration.
5. Add global ingress protection and decide how rejected/no-op control attempts are recorded without leaking secrets.
6. Preserve transactional pause behavior and verify concurrent reserve/claim calls cannot pass the persisted pause state.
7. Verify resume does not dispatch queued tasks and pause does not falsely claim to stop already-running side effects.
8. Confirm the audit trail does not contain credentials, cookies, task payloads, or sensitive personal data.
9. Verify Free plan and actual usage headroom before creating any namespace, binding, secret, or deployed control-plane resource.
10. Run targeted tests and isolated Preview smoke only after the above prerequisites; preserve the Draft PR and do not merge as part of this ADR update.

## Rollback and explicit non-goals

- Keep `AGENT_ENABLED=false` and `AGENT_PAUSED=true` by default.
- Rollback remains an isolated Preview code/config revert; do not delete or mutate Production resources.
- No public admin dashboard, direct browser-to-Durable-Object call, task handler, external side effect, scheduler, alarm, cron, automatic recovery, or 24/7 execution is authorized here.
- No changes to Production Worker, DNS, D1, secrets, routes, live user data, billing, or paid settings.


## GitHub Actions OIDC emergency-pause path (2026-11-20)

The Worker now accepts a GitHub Actions JWT at `POST /internal/oidc/pause` only when `AGENT_OIDC_ENABLED=true`. The route validates a strict three-segment bearer JWT before network access, loads signing keys only from the fixed GitHub issuer, validates the exact repository, immutable repository/owner IDs, `refs/heads/main`, exact workflow path, custom audience, `workflow_dispatch`, and an explicitly configured numeric actor ID. It consumes the verified token's `jti` through the fixed State Store client before the Pause mutation; replay, malformed policy, unavailable JWKS, and unavailable State Store all fail closed. The audit actor is derived from the verified `actor_id`, never from caller JSON. The route does not expose Resume, Recovery, task execution, or a generic operation selector.

The repository Preview config sets `AGENT_OIDC_ENABLED=true` and pins `AGENT_OIDC_ACTOR_ID="342528485"`; the other runtime safety flags remain disabled/paused and reviewer authentication remains disabled. The manual workflow is restricted to the dedicated repository, main ref, exact workflow identity, and Pause-only operation. The workflow/route source in this Draft PR is not evidence that the current PR head is deployed to the dedicated Worker. The workflow file remains subject to its branch and environment guards; no URL or secret value has been added to the repository.
